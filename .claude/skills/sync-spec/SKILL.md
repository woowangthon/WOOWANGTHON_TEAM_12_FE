# sync-spec

SPEC 은 ETC `docs/SPEC.md` 하나다. 여기 옮겨진 것만 개발 요구사항이다.

1. 입력(회의 메모 · 대화 · 구현 중 발견)에서 **확정 · 가설 · 미결정**을 가른다. 확정만 반영한다. 미결정은 「미결정 질문」 표로.
2. 있는 `R-` / `F-` / `S-` 를 고치거나 하위 `S-` 를 더하는 쪽을 먼저 본다. 새 ID 는 이어서 붙이고, 쓴 번호는 다시 쓰지 않는다. 없앨 땐 `(폐기)`.
3. 명세와 현실이 부딪치면(만들 수 없다 · 시간이 모자란다): 기존대로 갈 때의 위험, 대안 2~3개, 권장안 하나를 낸다. 데모를 깎는 안은 「무엇을 보면 그쪽으로 내리나」 조건과 함께.
4. 변경 요약 · 대상 항목 · 영향받는 이슈와 계약을 보여 주고, ETC 에 브랜치 `docs/<이슈번호|날짜>-spec-<짧은-이름>` → PR. 승인은 받지 않는다 — 5번 알림을 단 뒤 머지한다(`AGENTS.md` 머지 규칙 4 · ADR-006).
5. 영향받는 이슈에 댓글로 무엇이 바뀌었나 한 줄과 PR 링크. 완료 조건이 바뀌면 본문도 고친다.
6. 계약까지 바뀌면 `docs/contracts/` 를 같은 PR 에서.
7. Notion 커넥터를 쓸 수 있으면 그 결정이 나온 Notion 논의 페이지(「정한 것」 절 등)에 날짜 · 한 줄 · PR 링크를 남긴다. 쓸 수 없으면 보고에 「노션에 남길 한 줄」을 적어 사람에게 넘긴다.
