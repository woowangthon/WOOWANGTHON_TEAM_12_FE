# next-up

이슈 담당을 미리 정하지 않고 시간 · 토큰이 남는 사람이 가져가는 방식이라(ADR-002), **추천 순서** — 위에서부터 가져가면 막히지 않는 순서 — 를 **계산해서** 보여 준다. 순번 라벨을 붙이지 않는다 — 선행이 끝나도 그대로 남아 금방 낡는다. GitHub 의 선행(blocked by) · 하위 이슈 연결을 읽어 매번 계산한다.

## 절차

1. 모은다 — 이 스킬 폴더의 `collect.sh` 가 네 레포의 열린 Milestone · 열린 이슈 · 열린 선행 · 열린 하위 이슈를 한 번에 뽑는다(어느 레포에서 돌려도 결과가 같다).

   ```bash
   bash .claude/skills/next-up/collect.sh
   ```

2. **지금 스프린트** = 열린 Milestone 중 `스프린트 N` 의 N 이 가장 작은 것. 설명 칸이 그 스프린트의 목표 흐름이다.
3. **하위 이슈가 열려 있는 이슈(epic 등)는 추천 대상에서 뺀다** — 하위 이슈를 추천하고, 부모는 기능별 현황의 묶음 제목으로 남긴다. 하위 이슈가 없는 `epic` 은 「구현」이 아니라 「`plan-feature` 로 쪼개기」로 표시한다.
4. 위상 정렬 — 열린 선행이 있는 이슈는 그 선행보다 반드시 뒤. 같은 단계 안에서는:
   1. 지금 스프린트 → 다음 스프린트 → Milestone 없음(`P2` 백로그)
   2. 다른 이슈를 많이 막고 있는 것 먼저
   3. `P0` → `P1` → `P2`
5. 이슈마다 상태를 붙인다:
   - **지금 가능** — 담당 없음 + 열린 선행 없음
   - **목으로 먼저** — 담당 없음 + 열린 선행이 계약 이슈(ETC `docs` 라벨 · 제목 「계약」)뿐이고, 본문 「선행 이슈」에 「계약 전엔 … 시작해도 된다」가 있는 것
   - **진행 중** — 담당 있음. 연결된 PR 이 있으면 같이(`gh pr list -R <레포> --search "<번호> in:body" --state open`)
   - **대기** — 나머지. 무엇을 기다리는지(열린 선행)를 같이
6. 「진행 중」을 제외한 추천 대상에 4번 순서대로 **전역 추천 번호**를 붙인다. 그중 「지금 가능 · 목으로 먼저」인 작업을 순서대로 최대 3개 골라 맨 위에 요약한다. 3개보다 적으면 있는 만큼만, 하나도 없으면 「지금 가져갈 작업 없음」과 기다리는 이유를 쓴다.
7. 수집한 GitHub 하위 이슈 연결을 거꾸로 읽어 부모별로 묶는다. `epic` 라벨 유무와 관계없이 실제 연결을 따르고, 제목 · SPEC 번호가 비슷하다는 이유로 묶지 않는다. 중첩된 부모는 트리로, 부모 연결이 없는 작업은 「독립 작업」으로 보여 준다. 부모의 담당 · 선행을 하위 이슈에 물려주지 않는다.
8. 선행 연결이 본문과 어긋나 보이면(본문엔 선행이 있는데 「열린 선행」이 `-`) 출력 끝에 한 줄: 「`plan-feature/link.sh check` 로 확인 — 연결이 빠지면 순서가 틀린다」.

## 출력 형식

**지금 가져갈 추천을 먼저, 기능별 현황을 그 아래에 보여 준다.** 묶더라도 추천 번호는 다시 매기지 않는다. 묶음의 표시 순서가 실행 순서를 뜻하지는 않는다.

```
## 스프린트 N — <목표 흐름>
닫힘 a / 전체 b (ETC · FE · BE · AI 합계)

## 지금 추천 (최대 3개)
추천 1 · ETC#6 계약 — 지금 가능 · P0 · 3개를 풀어 준다(BE#4 · AI#4 · FE#5)
추천 2 · FE#4 셋업 + 미리보기 — 지금 가능 · P0 · 1개를 풀어 준다
추천 3 · ETC#7 디자인 시안 — 지금 가능 · P0

> 번호는 전체 작업의 추천 순서다. 실제 조건은 각 줄의 「기다림」뿐 — 영역이 다르면 번호를 건너뛰어도 된다.

## 기능별 현황
### ETC#1 경험 입력
- ETC#6 계약 — 지금 가능 · 추천 1 · P0
- BE#4 저장 · 조회 API — 목으로 먼저 · 추천 4 (기다림: ETC#6)
- AI#4 추출 — 목으로 먼저 · 추천 5 (기다림: ETC#6)
- FE#5 타임라인 — 대기 · 추천 6 (기다림: FE#4 · BE#4)

### 독립 작업
- FE#4 셋업 + 미리보기 — 지금 가능 · 추천 2 · P0
- ETC#7 디자인 시안 — 지금 가능 · 추천 3 · P0

### ETC#2 답변 생성
- FE#6 결과 화면 — 대기 · 추천 7 (기다림: AI#5)
- AI#5 생성 API — 진행 중 · @담당 · PR AI#12

## 백로그 (스프린트 밖)
### 독립 작업
- ETC#8 캘린더 — 지금 가능 · 추천 8 · P2
- ETC#9 공고 수집 — 지금 가능 · 추천 9 · P2
```

- 전역 추천 번호는 4번 위상 정렬 그대로. 「진행 중」은 번호와 상단 추천을 붙이지 않고, 소속 묶음 안에 담당 · PR 과 함께 표시한다.
- 묶음은 포함된 작업의 가장 빠른 추천 번호순, 묶음 안의 작업도 추천 번호순으로 쓴다. 번호 없는 진행 중 작업은 그 묶음의 뒤에 놓고, 진행 중 작업만 있는 묶음은 번호 있는 묶음 뒤에 놓는다. 중첩된 묶음에도 같은 기준을 적용한다.
- 상단 추천 요약을 제외하면 각 작업은 현황에 한 번만 쓴다. 진행 중 목록을 따로 반복하지 않는다. 부모는 제목만, 하위 작업은 상태와 함께 모두 보여 준다.
- 스프린트 밖 작업은 「백로그」에서도 같은 부모별 묶음을 쓴다. 부모와 하위 작업의 Milestone 이 다르면 **각 작업의 Milestone**으로 나누고 필요한 부모 제목만 반복한다. 하위 작업이 남았다는 이유로 부모를 별도 추천하거나 중복 집계하지 않는다.
- 「N개를 풀어 준다」 = 그 이슈를 직접이든 간접이든 기다리는 열린 이슈 수.
- 이슈마다 레포(ETC · FE · BE · AI)가 보이게 쓴다 — 읽는 사람이 자기 영역을 고른다.
- 사용자가 「내가 가져갈 거」라고 영역을 말했으면(「FE 쪽」) 상단 추천은 그 영역의 「지금 가능 · 목으로 먼저」에서 최대 3개 고른다. 전역 추천 번호와 아래 전체 현황은 유지한다.
- 지금 스프린트의 이슈가 다 닫혔으면 맨 위에 한 줄: 「스프린트 N 흐름이 다 닫혔다 — PM 이 써 보고 피드백 → 다음 스프린트 SPEC 을 채운다(ADR-002)」.

## 경계

- **읽기만 한다.** 담당을 걸거나 이슈 · Milestone 을 바꾸지 않는다. 가져가는 건 `implement-issue` 가 시작할 때 한다.
- 이어서 `implement-issue` 나 `plan-feature` 로 자동으로 넘어가지 않는다 — 고르는 건 사람이다.
