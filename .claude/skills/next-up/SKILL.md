# next-up

GitHub의 우선순위 · 선행(blocked by) · 부모/하위 연결을 읽어 **레포를 가로지르는 에픽 묶음**으로 보여 준다. 이슈를 바꾸거나 구현을 시작하지 않는다.

## 수집과 상태

1. 이 스킬 폴더의 `collect.sh`로 네 레포의 열린 Milestone · 이슈 · 선행 · 하위 이슈를 모은다.

   ```bash
   bash .claude/skills/next-up/collect.sh
   ```

2. **지금 스프린트**는 열린 Milestone 중 `스프린트 N`의 N이 가장 작은 것. 설명은 목표 흐름이다. 없으면 「열린 스프린트 없음」. 진행 수치는 네 레포의 같은 스프린트를 합산한다.
3. 실제 GitHub 하위 연결로 부모와 자식을 묶는다. `epic` 라벨 · 비슷한 제목 · SPEC 번호만으로 관계를 추측하지 않는다. 본문의 하위 목록과 수집 결과가 다르면 전체 하위 목록을 확인한다.
   - `gh api repos/<소유자>/<레포>/issues/<번호>/sub_issues --paginate`
   - 열린 자식의 부모가 수집에 없으면 부모를 조회해 확인한다. 닫힌 부모는 관계를 설명하는 제목으로만 쓰고 열린 작업으로 세지 않는다.
   - 중첩 부모도 실제 계층대로 묶는다. 부모의 담당 · 선행 · Milestone · 우선순위는 자식에게 물려주지 않는다.
4. 상태는 이슈마다 판단한다.
   - **가능**: 담당 없음 + 열린 선행 없음.
   - **목으로 먼저**: 담당 없음 + 열린 선행이 계약 이슈(ETC `docs` 라벨 · 제목 「계약」)뿐이고, 본문에 계약 전 목으로 시작해도 된다고 명시됨.
   - **진행 중**: 담당 있음. 상세 목록에서는 숨기고 마지막에 개수만 표시한다. PR · 담당 이름을 나열하지 않는다.
   - **대기**: 나머지. 열린 선행을 빠짐없이 링크한다. 목으로 먼저인 작업도 열린 선행이 있으면 함께 표시한다.
   - 열린 자식이 있는 부모: **열린 하위 n개**. 담당이 있어도 미담당 자식을 묶는 제목으로만 부모 키 · 짧은 제목을 쓸 수 있다. 부모 담당을 자식 담당으로 해석하지 않는다.
   - 열린 자식이 없는 `epic`: 전체 하위 목록을 확인한다. 하위가 없으면 **계획 필요**, 모두 닫혔으면 **잔여 범위 확인 · 하위 a/a 닫힘**. `not_planned`로 닫힌 자식은 완료로 단정하지 않는다. 부모 본문 · SPEC · 관련 열린 이슈에 남은 범위가 있으면 한 줄로 표시한다. 이 스킬은 부모를 자동으로 닫지 않는다.
5. 본문에 선행이 있는데 수집한 열린 선행이 없다면 닫힌 선행인지 확인한다. 연결 누락이 의심되면 끝에 「`plan-feature/link.sh check`로 선행 연결 확인 필요」와 해당 이슈를 쓴다. 순환 · 조회 실패 · 미수집 선행도 원인을 표시하고 임의로 가능 처리하지 않는다.

## 묶음과 정렬

- 표 · 추천 순번 · 체크박스를 쓰지 않는다. **P0 → P1 → P2 → 우선순위 미지정** 순으로 제목을 두고, 각 제목 아래 에픽 묶음과 독립 작업을 둔다. 빈 우선순위 제목은 생략한다.
- 같은 에픽의 부모와 자식은 FE · BE · AI · ETC를 한 묶음에서 읽는다. 레포별 표나 별도 진행 중 목록으로 흩뜨리지 않는다. 독립 작업은 해당 우선순위 아래 한 줄로 둔다.
- **묶음의 우선순위는 P3를 제외한 열린 부모·표시할 자식 중 가장 높은 우선순위**다. 예: P1 부모 아래 P2 자식은 P1 묶음 안에 두고 자식에 `P2`를 그대로 적는다. 라벨을 바꾸거나 자식에게 부모 값을 물려주지 않는다. 이슈는 자기 작업 줄에서 한 번만 나열한다.
- 같은 우선순위의 묶음은 지금 스프린트 → 다음 스프린트(N 오름차순) → 기타 Milestone(제목순) → Milestone 없음 순이다. 묶음의 스프린트 정렬 키는 표시 대상 열린 이슈 중 가장 앞선 스프린트다. 다음으로 다른 열린 작업을 많이 풀어 주는 묶음(직접·간접 후속을 중복 없이 셈) → 대표 이슈 키순으로 고른다. 키의 레포 순서는 FE · BE · AI · ETC, 번호는 숫자순이다.
- 묶음 안에서는 계층을 유지하고, 같은 부모의 형제끼리 **각자의 P0 → P1 → P2 → 미지정** 순으로 둔다. 같은 우선순위에서는 선행 작업 → 스프린트 → 풀어 주는 수 → 이슈 키순이다.
- **우선순위가 정렬의 첫 기준이다.** 낮은 우선순위의 선행을 앞으로 끌어올리지 않는다. 선행은 `대기: BE#…`처럼 실제 시작 조건으로 표시한다. 대기를 건너뛰고 가능한 작업을 가져가면 된다.

## 진행 중 숨기기

- 담당이 있는 열린 P0~P2 · 우선순위 미지정 이슈는 작업 줄에서 숨기고 맨 아래 **「진행 중은 상세 생략: 총 n개(FE a · BE b · AI c · ETC d)」** 한 줄로 표시한다. 부모도 이슈별 한 번씩 세되, P3는 아래 P3 집계에만 넣어 두 집계가 겹치지 않게 한다.
- 담당 있는 부모 아래 미담당 자식은 계속 표시한다. 부모는 묶음 제목으로만 사용하고 담당 · PR · 진행 상세를 쓰지 않는다. 표시할 자식이 없는 진행 중 묶음은 제목째 생략한다. 담당 없는 부모도 열린 자식 전부가 진행 중 또는 P3라면 빈 묶음을 만들지 않는다.
- 숨긴 진행 중 이슈도 선행 판단과 전체 하위 수에는 포함한다. 표시 작업이 기다리는 선행이면 대기 이유에만 링크와 `진행 중`을 짧게 쓴다. 그 밖에는 진행 중 이슈 제목 · 담당 · PR을 펼치지 않는다.

## P3 숨기기

- P3는 원본 데이터에서 수집하되 본문의 작업 목록에서는 숨긴다. 맨 아래 **「P3는 상세 생략: 총 n개(FE a · BE b · AI c · ETC d)」** 한 줄만 쓴다. 열린 P3 이슈를 각각 한 번씩 세며 부모도 포함한다. P3가 없으면 「P3 0개」만 쓴다.
- 숨긴 P3도 선행 판단과 하위 진행 수에는 포함한다. 표시 작업이 P3를 기다리면 그 작업의 대기 이유에만 이슈 링크와 `P3`를 표시한다. 숨긴 선행을 없는 것으로 취급하지 않는다.
- P3 부모 아래 P0~P2 자식이 있으면 자식은 해당 우선순위에 표시한다. 부모의 상세 작업 줄은 생략하고 관계 설명에 필요할 때만 부모 키를 짧게 덧붙인다. P3 자식은 펼치지 않고 부모에 「P3 하위 n개 생략」으로 알린다.

## 경계

- **읽기만 한다.** 담당 · 이슈 · Milestone을 바꾸지 않는다. 가져가는 건 `implement-issue`가 시작할 때 한다.
- 이어서 구현 · 이슈 분해 · 부모 종료로 자동 전환하지 않는다. 사용자가 따로 요청한 작업은 그 요청 범위에서 처리한다.
