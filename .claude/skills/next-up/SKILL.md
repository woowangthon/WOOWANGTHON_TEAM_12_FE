# next-up

이슈 담당을 미리 정하지 않고 시간 · 토큰이 남는 사람이 가져가는 방식이라(ADR-002), **추천 순서** — 위에서부터 가져가면 막히지 않는 순서 — 를 **계산해서** 보여 준다. 순번 라벨을 붙이지 않는다 — 선행이 끝나도 그대로 남아 금방 낡는다. GitHub 의 선행(blocked by) · 하위 이슈 연결을 읽어 매번 계산한다.

## 절차

1. 모은다 — 이 스킬 폴더의 `collect.sh` 가 네 레포의 열린 Milestone · 열린 이슈 · 열린 선행 · 열린 하위 이슈를 한 번에 뽑는다(어느 레포에서 돌려도 결과가 같다).

   ```bash
   bash .claude/skills/next-up/collect.sh
   ```

2. **지금 스프린트** = 열린 Milestone 중 `스프린트 N` 의 N 이 가장 작은 것. 설명 칸이 그 스프린트의 목표 흐름이다.
3. **하위 이슈가 열려 있는 이슈(epic 등)는 목록에서 뺀다** — 그 자리를 하위 이슈가 잇는다. 하위 이슈가 없는 `epic` 은 「구현」이 아니라 「`plan-feature` 로 쪼개기」로 표시한다.
4. 위상 정렬 — 열린 선행이 있는 이슈는 그 선행보다 반드시 뒤. 같은 단계 안에서는:
   1. 지금 스프린트 → 다음 스프린트 → Milestone 없음(`P2` 백로그)
   2. 다른 이슈를 많이 막고 있는 것 먼저
   3. `P0` → `P1` → `P2`
5. 이슈마다 상태를 붙인다:
   - **지금 가능** — 담당 없음 + 열린 선행 없음
   - **목으로 먼저** — 담당 없음 + 열린 선행이 계약 이슈(ETC `docs` 라벨 · 제목 「계약」)뿐이고, 본문 「선행 이슈」에 「계약 전엔 … 시작해도 된다」가 있는 것
   - **진행 중** — 담당 있음. 연결된 PR 이 있으면 같이(`gh pr list -R <레포> --search "<번호> in:body" --state open`)
   - **대기** — 나머지. 무엇을 기다리는지(열린 선행)를 같이
6. 선행 연결이 본문과 어긋나 보이면(본문엔 선행이 있는데 「열린 선행」이 `-`) 출력 끝에 한 줄: 「`plan-feature/link.sh check` 로 확인 — 연결이 빠지면 순서가 틀린다」.

## 출력 형식

**추천 순서가 본론이다.** 위에서부터 하나씩 가져가면 막히는 일이 없는 순서 — 1번이 가장 먼저 할 일.

```
## 스프린트 N — <목표 흐름>
닫힘 a / 전체 b (ETC · FE · BE · AI 합계)

## 추천 순서
1. ETC#6 계약 — 지금 가능 · P0 · 4개를 풀어 준다(BE#4 · BE#5 · AI#4 …)
2. FE#4 셋업 + 미리보기 — 지금 가능 · P0 · 2개를 풀어 준다
3. ETC#7 디자인 시안 — 지금 가능 · P0
4. BE#4 저장 · 조회 API — 목으로 먼저 (기다림: ETC#6)
5. AI#4 추출 — 목으로 먼저 (기다림: ETC#6)
6. FE#5 타임라인 — 대기 (기다림: FE#4)
...

> 번호는 추천일 뿐이다. 실제 조건은 각 줄의 「기다림」뿐 — 영역이 다르면 번호를 건너뛰어도 된다(FE 담당은 FE 줄 중 가장 위부터).

## 진행 중
- BE#4 — @담당 · PR #12

## 백로그 (스프린트 밖)
- ETC#8 캘린더 · ETC#9 공고 수집
```

- 순서는 4번 위상 정렬 그대로. 「진행 중」인 이슈는 추천 순서에서 빼고 「진행 중」에만 쓴다.
- 「N개를 풀어 준다」 = 그 이슈를 직접이든 간접이든 기다리는 열린 이슈 수.
- 이슈마다 레포(ETC · FE · BE · AI)가 보이게 쓴다 — 읽는 사람이 자기 영역을 고른다.
- 사용자가 「내가 가져갈 거」라고 영역을 말했으면(「FE 쪽」) 추천 순서에서 그 영역의 「지금 가능 · 목으로 먼저」 줄을 맨 위에 따로 한 번 더 보여 준다.
- 지금 스프린트의 이슈가 다 닫혔으면 맨 위에 한 줄: 「스프린트 N 흐름이 다 닫혔다 — PM 이 써 보고 피드백 → 다음 스프린트 SPEC 을 채운다(ADR-002)」.

## 경계

- **읽기만 한다.** 담당을 걸거나 이슈 · Milestone 을 바꾸지 않는다. 가져가는 건 `implement-issue` 가 시작할 때 한다.
- 이어서 `implement-issue` 나 `plan-feature` 로 자동으로 넘어가지 않는다 — 고르는 건 사람이다.
