2026-11-06 실행. FE localhost:3000, BE :8080, AI :8000, PostgreSQL :5432를 사용했습니다. 입력은 테스트용이며 응답은 실제 서버·DB에서 받았습니다. API Mock을 사용한 회귀 검사는 아래에 별도로 구분했습니다.

## 발견 및 수정

문항 정보가 늦게 도착하면 복원된 차곡이 확인 카드 위에 Feed가 추가되어 승인 버튼이 스크롤 아래로 밀렸습니다. 기존 존재 확인만으로는 놓칠 수 있었습니다.

- `src/components/questions/use-chagok-run.ts`: 복원 중인 runId를 패널에 제공합니다.
- `src/components/questions/chagok-panel.tsx`: 복원 작업의 문항 ID·상태 변경 시 스크롤을 다시 맞춥니다. 일반 문항의 기존 스크롤 동작과 상세 폴링은 유지합니다.
- `tests/global-work.spec.ts`: 늦게 도착하는 문항 Feed 후 버튼이 viewport 안에 남는 회귀 검사를 추가했습니다.

실제 BE·AI로 추천·차곡이 작업을 다시 실행하여 PC·모바일에서 문항 Feed 로딩과 새로고침 후 버튼의 viewport 진입을 확인했습니다. 승인 버튼은 누르지 않았습니다.

## AI 호출 및 데이터

실제 AI 작업 요청은 총 **8건**입니다: 자료 분석 2, 문항 추천 2, 초안 1, 근거 점검 1, 차곡이 2. 결과는 COMPLETED 6건, WAITING_CONFIRM 2건입니다. AI 서비스 접근 로그에서도 extract 2, match 2, draft 1, ground-check 1, agent 2의 HTTP 200을 확인했습니다.

외부 모델 제공자에 대한 물리적 HTTP 호출 수·SDK 재시도·에이전트 내부 모델 턴 수는 로그가 노출되지 않아 **미측정**입니다. 8건은 애플리케이션 작업 요청 수이며 외부 LLM 호출 수로 간주하지 않습니다.

기존 로그인 세션을 추출하는 대신 새 격리 테스트 계정 4개(userId 3·4·5·6)를 만들었습니다. 비밀번호는 메모리에서만 사용하고 세션·토큰·키를 결과 파일에 저장하지 않았습니다. 해당 계정으로 만든 자료·지원만 사용했고 기존 사용자 데이터는 수정·삭제하지 않았습니다. 테스트 데이터는 남겨 두었습니다.

읽기 전용 SQL로 해당 계정 소유 행만 확인했습니다: source 2, analysis_job 2, application 2, question 2, draft 1, grounding_check 1, chagok_run 2. DB 직접 변경 쿼리는 실행하지 않았습니다. 행 수 원시 출력은 로컬에만 보관합니다.
